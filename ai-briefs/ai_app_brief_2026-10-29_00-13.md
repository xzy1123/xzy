## 官方产品 / 平台更新

**Legora 用 OpenAI 模型搭法律工作的 Agent 操作系统**
[链接](https://openai.com/index/legora-agentic-operating-system-for-legal-work)
为什么值得关注：法律是文档密集、流程固定的场景，正好适合 Agent 切入。Legora 用 ChatGPT 和 Codex 做合同分析和流程自动化，是“垂直行业 + Agent”的典型落地案例，做企业应用的可以对照看自己的场景。

**Retell 用 OpenAI 模型支撑每月 1 亿通电话**
[链接](https://openai.com/index/retell-ai)
为什么值得关注：语音 Agent 已经跑到大规模商用。GPT-6 Astra 在其语音 Agent 评测中排第一，Codex 帮它做到每名员工 160 万美元年化收入。关注点是：语音客服这类场景的单位经济模型已经能跑通。

**OpenAI 扩大与 Oracle 合作，把企业应用接进 ChatGPT**
[链接](https://openai.com/index/oracle-apps-in-chatgpt)
为什么值得关注：企业软件正在往聊天入口里搬。对做企业内部工具的团队来说，这意味着“在 ChatGPT 里调用业务系统”可能成为新的集成方式，值得提前想接口怎么设计。

**NVIDIA 发布 Nemotron 3.5 Transcribe 和 Granary v2**
[链接](https://huggingface.co/blog/nvidia/nemotron-transcribe-granary)
为什么值得关注：多语言转写支持提示词调节，适合做会议记录、客服质检这类需要适配不同语种和口音的产品。可以直接拿来试，省掉自研转写模型的成本。

**LFM3：构建专用多模态模型**
[链接](https://huggingface.co/blog/LiquidAI/lfm3)
为什么值得关注：专用小模型在多模态内容生产上越来越实用。如果你的场景固定（比如商品图、短视频素材），不一定非要上大模型。

## 新产品 / 新工具

**Trigger.dev：给 AI Agent 加 Webhook**
[链接](https://www.producthunt.com/products/trigger-dev)
为什么值得关注：Agent 要真正干活，就得能被外部事件触发。它支持 Slack、Supabase 等 50+ 服务，适合做“收到消息就自动处理”的自动化流程。

**BotGauge**
[链接](https://www.producthunt.com/products/botgauge-2)
为什么值得关注：定位是 Agent 的“信任层”，也就是监控和评估 Agent 行为是否可靠。Agent 上生产后，这类可观测工具会越来越刚需。

**App Store Screenshots**
[链接](https://www.producthunt.com/products/app-store-screenshots)
为什么值得关注：让编码 Agent 直接生成应用商店截图，是“Agent 干完整交付”的一个小切口。独立开发者可以省掉设计外包。

**Dedica**
[链接](https://www.producthunt.com/products/dedica)
为什么值得关注：检测 AI Agent 能不能用你的网站。做面向 Agent 的产品时，这是个很实际的检查项——你的页面结构 Agent 读得懂吗？

**Our Silly Games**
[链接](https://www.producthunt.com/products/our-silly-games)
为什么值得关注：用 Claude 的 Skills 做游戏，还带免费多人托管。适合快速验证小游戏想法，不用自己搭后端。

**Yardlet**
[链接](https://www.producthunt.com/products/yardlet-2)
为什么值得关注：把已经在用的编码 Agent 收进一个 Mac 应用里管理。多 Agent 切换的人可以看看交互设计。

## 开源项目 / 工程落地

**NousResearch/hermes-agent**
[链接](https://github.com/NousResearch/hermes-agent)
为什么值得关注：主打“随你成长的 Agent”，强调长期使用中的能力积累。想自建 Agent 底座可以看它的架构思路。

**ComposioHQ/composio**
[链接](https://github.com/ComposioHQ/composio)
为什么值得关注：1000+ 工具集成、工具检索、上下文管理、鉴权和沙箱工作台，基本把 Agent 接外部工具要踩的坑都包了。自建 Agent 时能省大量集成工作。

**deepset-ai/haystack**
[链接](https://github.com/deepset-ai/haystack)
为什么值得关注：老牌开源编排框架，主打模块化管线和生产可用。适合需要可控、可维护的 LLM 应用，而不是一把梭的 demo。

**semantica-agi/semantica**
[链接](https://github.com/semantica-agi/semantica)
为什么值得关注：图原生的上下文基础设施，强调“可问责的 AI 系统”。对需要追溯数据来源、做合规的场景有参考价值。

**kirodotdev/KiroCrew**
[链接](https://github.com/kirodotdev/KiroCrew)
为什么值得关注：持久化开发工作区，能跨会话继续并自我改进。解决的是“每次开新会话都从零开始”的痛点。

**crmne/ruby_llm**
[链接](https://github.com/crmne/ruby_llm)
为什么值得关注：Ruby 生态的 AI 框架。如果团队技术栈是 Rails，不用为了接模型硬换语言。

## 研究转应用信号

**Trinity：多模态 Agent 的能力驱动递归自我改进**
[链接](https://huggingface.co/papers/2610.36077)
为什么值得关注：Agent 自我改进是长期方向，先留意它什么时候能变成产品能力。

**VibeVideoBench：评测多模态 Agent 的代码驱动视频生成**
[链接](https://huggingface.co/papers/2610.35864)
为什么值得关注：代码生成视频是可落地的内容生产方向，这个基准能帮你判断模型够不够用。

**HABIT-Bench：从长期弱证据中评测 Agent 记忆的习惯归纳**
[链接](https://huggingface.co/papers/2610.24520)
为什么值得关注：Agent 要长期用，就得从零散信息里总结用户习惯。这是记忆产品的关键能力。

**Memory Tax：拆解 Agent 记忆的净价值**
[链接](https://huggingface.co/papers/2610.34073)
为什么值得关注：记忆不是免费的，有存储和检索成本。上线记忆功能前，值得算算它到底带来多少净收益。

**面向长程 LLM Agent 的多尺度策略优化**
[链接](https://huggingface.co/papers/2610.35013)
为什么值得关注：长任务 Agent 的稳定性是落地瓶颈，这个方向进展会影响自动化流程能跑多长。

**该选多高的推理强度？LLM Agent 推理成本的经济学**
[链接](https://huggingface.co/papers/2610.34491)
为什么值得关注：推理强度直接关系到成本和延迟。做 Agent 产品时，这是个必须调的参数，不是越高越好。
