## 官方产品 / 平台更新

**OpenAI 让网站更容易表达 AI 训练偏好**
OpenAI 会遵守一个共享的 robots.txt 信号，让网站运营方把训练偏好告诉参与方。
为什么值得关注：做内容站、数据平台或爬虫相关产品的团队，多了一个可落地的合规表达方式，不用只靠条款扯皮。
[链接](https://openai.com/index/helping-websites-express-ai-training-preferences)

**OpenAI 社区安全报告与青少年保护**
ChatGPT 加强暴力预防，增加更早的干预和公共安全承诺。
为什么值得关注：面向青少年或教育场景做应用，平台侧的安全边界在收紧，产品设计要提前留出审核和干预入口。
[链接](https://openai.com/index/community-safety-report-and-new-protections-for-teens)

**OpenAI 更新 Model Spec**
新版 Model Spec 列出五项核心价值，用来指导模型判断、尊重人的自主性并保持对人类意图的忠实。
为什么值得关注：做 Agent 或自动决策产品时，这份规范可以作为写系统提示和设定行为边界的参考。
[链接](https://openai.com/index/updated-model-spec)

**Granite Switch 4.1.1：像更新软件一样更新模型**
IBM Granite 发布 4.1.1 更新。
为什么值得关注：企业选模型底座时，“能不能像软件一样平滑升级”比单次跑分更影响长期维护成本。
[链接](https://huggingface.co/blog/ibm-granite/granite-switch-4-1-1)

**nemotron-halloween**
NVIDIA 在 Hugging Face 发布 Nemotron 相关博客。
为什么值得关注：模型发布节奏快，做应用选型的人可以顺手看看有没有适合自己场景的轻量选项。
[链接](https://huggingface.co/blog/nvidia/nemotron-halloween)

## 开源项目 / 工程落地

**yamadashy/repomix**
把整个仓库打包成一个 AI 友好的文件，方便把代码喂给模型。
为什么值得关注：做代码问答、审查或迁移时，先把上下文整理好往往比换模型更有效，这个工具直接解决“怎么喂”。
[链接](https://github.com/yamadashy/repomix)

**rlaope/oh-my-hermes**
把 Hermes Agent 接进 IDE 的编码工具链。
为什么值得关注：Agent 进 IDE 是当前落地最快的一类场景，适合想在自己编辑器里试 Agent 工作流的开发者。
[链接](https://github.com/rlaope/oh-my-hermes)

**kirodotdev/KiroCrew**
一个能自我改进、跨会话持续工作的开发工作区。
为什么值得关注：“持久工作区”是 Agent 从单次对话走向长期任务的关键，值得观察它怎么处理上下文和状态。
[链接](https://github.com/kirodotdev/KiroCrew)

**crmne/ruby_llm**
Ruby 的 AI 框架。
为什么值得关注：Ruby 团队接大模型的选择一直偏少，这类框架能让 Rails 项目少绕路。
[链接](https://github.com/crmne/ruby_llm)

**wangzan101/Mika**
Android 上的端侧 AI Agent，能操作 App 和网页完成任务。
为什么值得关注：端侧 Agent 直接碰用户手机上的 App，落地想象空间大，但权限和稳定性要重点看。
[链接](https://github.com/wangzan101/Mika)

**nano-muse/nanoMuse**
开源个人 Agent，覆盖你拥有的多台设备。
为什么值得关注：个人 Agent 跨设备连续工作是很多人的期待，开源实现适合拿来改造成自己的工具。
[链接](https://github.com/nano-muse/nanoMuse)
