### Stampli 借助 ChatGPT Work 把上线耗时缩短 68%

[Stampli cuts launch hours by 68% using ChatGPT Work](https://openai.com/index/stampli)

Stampli 在设计与开发资源被占满的情况下，用 Codex 和 ChatGPT Work 把数周的上线准备工作压缩到极短时间。

**为什么值得关注**：这是一个典型的"小团队 + AI 代理"落地案例。代码生成不稀奇，"代理自动完成跨工具协作"才是关键——值得作为团队提效的参考样本。

### OpenAI 为零留存再添安全承诺

[Offering Zero Data Retention for frontier models](https://openai.com/index/offering-zero-data-retention-for-frontier-models)

OpenAI 重申符合条件的 API 客户默认零数据留存，并预告了"私有安全处理"机制，在不妥协安全性的前提下做高级安全分析。

**为什么值得关注**：数据合规是企业采用大模型API最大的顾虑之一。零留存加私有安全处理，等于给银行、医疗、法务等行业吃了定心丸。

### Replit 免费模式：人人可做软件

[Replit expands access to software creation with GPT-5.6 Luna](https://openai.com/index/replit)

Replit 推出免费模式，由 GPT-5.6 Luna 驱动，任何人都能把想法变成可用软件，不必担心 Token 费用。

**为什么值得关注**：Replit 定位是"AI 原生开发平台"，免费模式可能进一步拉低软件制作门槛。原型验证、内部工具、自动化脚本这类轻量需求，以后可能不用写代码了。

### LFM2.5-DSpark：推理提速 3.2 倍

[Up to 3.2x Faster Inference with LFM2.5-DSpark](https://huggingface.co/blog/LiquidAI/lfm25-dspark)

Liquid AI 发布新模型 LFM2.5-DSpark，主打超快推理性能。

**为什么值得关注**：推理速度直接决定 Agent 应用的响应体验和单位成本。如果 LFM2.5 在保持质量的同时做到 3.2 倍加速，走 API 路线的团队值得做一轮对比测试。

### Agent 到底需要多大内存？

[How Much Memory Does Your Agent Actually Need?](https://huggingface.co/blog/ibm-research/altk-evolve-hmm)

IBM Research 分析了 Agent 在工作记忆方面的真实需求。

**为什么值得关注**：上下文窗口不是越大越好。过大的上下文会显著推高成本和延迟。这个问题的工程答案，直接影响 Agent 架构设计。
